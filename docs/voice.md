# Voice guide

Write for a capable reader who has not seen the topic before.

- Direct and calm. Say what the code does, then what to do next.
- No cute metaphors, no cheerleading ("Great job!"), no condescension ("simply", "just", "easy").
- Define each new term once, in one plain sentence, the first time it appears.
- Name the exact thing: "the list `nums`", not "the data".
- Short sentences. Active voice. Present tense.
- Original prose only. Do not paraphrase other courses or sites.

## Every lesson has

1. `goal`: one sentence, what the function returns.
2. `teach`: 2 to 4 blocks. One worked example with real output.
3. `hints`: exactly 2. First points at the idea. Second names the tool or step. Neither contains the full answer.
4. `explainer`: 2 sentences on why the reference solution works.

## Messages to the learner

State what happened, where, and what to try. Never "Oops", "Uh oh" or exclamation marks.

Good: "The function returned None. Add a return statement that gives back the answer."
Bad: "Oops! Looks like something went wrong!"
